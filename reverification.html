Re-verification Walkthrough

How the 2026-09-05 disclosure-day sweep was run: one benign canary per endpoint, no bulk, no payload strings. Every check below is the exact shape used — substitute placeholders only with keys you are authorized to test.

Results: docs/reverification-2026-09-05.md TLP:CLEAR

Rules of the sweep

  • One benign synthetic event per endpoint. No bulk, no flooding, no retry loops.
  • No payload strings: no XSS, SQL, command-injection, or path-traversal content was sent. Only a unique harmless canary marker in a custom field.
  • Acceptance response = the ingestion boundary received and parsed the event. It does not prove storage, dashboards, alerts, or AI-training use. Vendors are the only party that can trace final disposition (see the whitepaper's canary-trace request).
  • Keys used were client-side tokens already embedded in public web JavaScript — the documented finding. Do not run these against systems you are not authorized to test.

1. Application Insights (Microsoft)

# one benign canary, no payload strings
CANARY="CoM-walkthru-$(date +%s)"
curl -s -X POST "https://eastus-8.in.applicationinsights.azure.com/v2.1/track" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Microsoft.ApplicationInsights.Event",
    "time": "'$(date -u +"%Y-%m-%dT%H:%M:%SZ")'",
    "iKey": "<IKEY>",
    "tags": {"ai.device.id": "'"$CANARY"'"},
    "data": {"baseType": "EventData",
             "baseData": {"ver": 2, "name": "ExternalProbe",
                          "properties": {"canary": "'"$CANARY"'"}}}
  }'

Observed (2026-09-05): HTTP 200 with {"itemsReceived":1,"itemsAccepted":1,"errors":[]} for the four Power BI / Fabric keys in the record. CarMax key 78f195a3… same; key 8384dafb… now returns 400 Invalid instrumentation key (rotated).

2. OneCollector / 1DS (Microsoft)

CANARY="CoM-walkthru-$(date +%s)"
curl -s -o /dev/null -w "HTTP %{http_code}\n" \
  "https://browser.events.data.microsoft.com/OneCollector/1.0/?cors=true&content-type=application%2Fx-json-stream&client-id=NO_AUTH&client-version=1DS-Web-JS-3.2.6&apikey=<APIKEY>&upload-time=$(date +%s%3N)&w=2&NoResponseBody=true" \
  -H "Content-Type: text/plain;charset=UTF-8" \
  -H "Origin: https://login.microsoftonline.com" \
  -d '{"name":"CoM.Canary","time":"'$(date -u +"%Y-%m-%dT%H:%M:%S.%3NZ")'","ver":"4.0","iKey":"o:<IKEY>","ext":{},"data":{"canary":"'"$CANARY"'"}}'

Observed (2026-09-05): HTTP 204 on both browser.events and vortex for both keys in the record — accepted with client-id=NO_AUTH. (The 09-04 "401" in earlier notes was a truncated-key test artifact; corrected in the re-verification doc.)

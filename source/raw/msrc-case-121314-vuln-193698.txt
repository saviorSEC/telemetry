Steps to Reproduce

Step 1: Access Gateway Admin Portal JavaScript Bundles

Navigate to any of the following gateway admin portal URLs in a web browser or using curl:

https://gatewayadminportal.azure.com

https://gatewayadminportal-devint.azure.com

https://gatewayadminportal-ppe.azure.com

https://gatewayadminportal-msit.azure.com

https://gatewayadminportal-test.azure.com

https://gatewayadminportal-tip.azure.com

https://gatewayadminportal-tip2.azure.com

https://gatewayadminportal-high.azure.us

https://gatewayadminportal-mil.azure.us

https://gatewayadminportal-canaryhigh.azure.us

https://gatewayadminportal-gov.azure.us

https://gatewayadminportal.azure.cn

Execute the following command to confirm the localization file is accessible:

curl -s -o /dev/null -w "%{http_code}\n" "https://gatewayadminportal.azure.com/localization/ClientStrings.en-US.js"

Expected result: HTTP 200

Step 2: Download Source Map for Full Code Decompilation

Execute the following commands to download the production bundle and source map:

curl -s -o bundle.js "https://gatewayadminportal-devint.azure.com/static/js/bundle.js"

curl -s -o bundle.js.map "https://gatewayadminportal-devint.azure.com/static/js/bundle.js.map"

Expected result: bundle.js is approximately 4.2MB. bundle.js.map is approximately 16.1MB and contains the complete TypeScript source map.

Step 3: Extract Internal IP Ranges from US Gov High Localization File

Execute the following command:

curl -sk "https://gatewayadminportal-high.azure.us/localization/ClientStrings.en-US.js" | grep -oE '10.[0-9]+.[0-9]+.[0-9]+/[0-9]+'

Expected result: 10.240.0.0/16 and 10.224.0.0/12 are displayed.

Step 4: Confirm Unauthenticated Telemetry Injection

Execute the following curl command using any of the confirmed Application Insights keys:

curl -X POST "https://eastus-8.in.applicationinsights.azure.com/v2.1/track" -H "Content-Type: application/json" -d '{"name":"Microsoft.ApplicationInsights.Event","time":"2026-06-06T20:00:00Z","iKey":"6a66a822-429e-49e0-951f-dbba255ac842","tags":{"ai.device.id":"recon"},"data":{"baseType":"EventData","baseData":{"ver":2,"name":"ExternalProbe"}}}'

Expected result: JSON response containing "itemsReceived":1,"itemsAccepted":1,"errors":[]

Repeat step 4 with the following additional instrumentation keys, each returns the same expected result:

e3524ec5-ee88-4933-a91e-4d16e385ef93

e43fee4d-90d5-4c2a-a681-cffdd604ad5c

433d8c1b-e63d-4935-8917-fbb39ecb7b51

Step 5: Generate OAuth Device Code for Microsoft Corporate Tenant

Execute the following command:

curl -X POST "https://login.microsoftonline.com/72f988bf-86f1-41af-91ab-2d7cd011db47/oauth2/v2.0/devicecode" -d "client_id=1950a258-227b-4e31-a9cf-717495945fc2" -d "scope=https://app.visualstudio.com/.default"

Expected result: JSON response containing "user_code","device_code","verification_uri":"https://login.microsoft.com/device"

Repeat step 5 with the following additional client ID:

curl -X POST "https://login.microsoftonline.com/72f988bf-86f1-41af-91ab-2d7cd011db47/oauth2/v2.0/devicecode" -d "client_id=065d9450-1e87-434e-ac2f-69af271549ed" -d "scope=https://admin.powerplatform.microsoft.com/.default"

Expected result: JSON response containing "user_code","device_code","verification_uri":"https://login.microsoft.com/device"

Step 6: Access Internal Power BI Deployments

Navigate to any of the following URLs or execute curl commands:

https://edog.analysis-df.windows.net

https://powerbi-df.analysis-df.windows.net

https://powerbi-wow-int3.analysis-df.windows.net

https://daily.powerbi.com

https://dxt.powerbi.com

https://msit.powerbi.com

Execute: curl -s -o /dev/null -w "%{http_code}\n" "https://edog.analysis-df.windows.net/"

Expected result: HTTP 200. The page loads JavaScript bundles from preprod.content.powerapps.com/resource/powerbiwfe/ similar to the gateway portals.

Step 7: Enumerate Service Bus Queues

Execute the following commands:

curl -s -o /dev/null -w "%{http_code}\n" "https://dogfood.servicebus.windows.net/powerbi"

curl -s -o /dev/null -w "%{http_code}\n" "https://dogfood.servicebus.windows.net/fabric"

curl -s -o /dev/null -w "%{http_code}\n" "https://dogfood.servicebus.windows.net/gateway"

curl -s -o /dev/null -w "%{http_code}\n" "https://dogfood.servicebus.windows.net/gatewayadmin"

curl -s -o /dev/null -w "%{http_code}\n" "https://dogfood.servicebus.windows.net/fabricapi"

Expected result: HTTP 401 for each queue name, confirming the queues exist and require authorization. Repeat with canary.servicebus.windows.net and staging.servicebus.windows.net.

Step 8: Access Power Platform Admin Center Configuration

Navigate to https://admin.powerplatform.microsoft.com/ and view page source.

Search for window._ppuxConfig.

Expected result: The full runtime configuration is displayed including aadClientId 065d9450-1e87-434e-ac2f-69af271549ed, region: prod, geo: US, and portalVersionedEndpoint URLs.

All steps can be executed from any external machine with internet access. No authentication, cookies, or special headers are required. All endpoints are publicly accessible Microsoft-owned infrastructure.
Description
Vulnerability Description

During external reconnaissance of Microsoft Power BI and Fabric infrastructure, the researcher discovered critical systemic security exposures across all gateway admin portals and internal deployments, plus unauthenticated telemetry injection capabilities.

Summary of Findings:

    All 12 gateway admin portals across global, pre-production, test, MSIT, TIP, US Government High, US Government Mil, US Government Canary High, and China (Mooncake) clouds expose identical JavaScript bundles and source maps containing complete TypeScript source code of the Gateway Admin Portal application.

    Six internal Power BI deployments (edog.analysis-df.windows.net, powerbi-df.analysis-df.windows.net, powerbi-wow-int3.analysis-df.windows.net, daily.powerbi.com, dxt.powerbi.com, msit.powerbi.com) expose the same JavaScript bundles, leaking internal Power BI application code from development, test, and MSIT environments.

    The source map file (bundle.js.map, 16,174,111 bytes) remains publicly accessible post-disclosure and has been fully decompiled, revealing 1,390 source files including internal mock frameworks, Azure AD role GUIDs, hardcoded test data, internal IP ranges, and Microsoft internal DevOps repository URLs.

    Four Application Insights instrumentation keys accept unauthenticated POST requests to eastus-8.in.applicationinsights.azure.com/v2.1/track, allowing arbitrary telemetry injection into Microsoft's internal monitoring systems. Live payloads returned itemsAccepted:1.

    The US Government High cloud portal serves a 113KB Microsoft Authenticode-signed localization file containing 1,200+ internal UI strings, 55+ DMTS error codes, and the internal IP ranges 10.240.0.0/16 and 10.224.0.0/12.

    Three Service Bus instances (dogfood.servicebus.windows.net, canary.servicebus.windows.net, staging.servicebus.windows.net) return public Atom feeds. Seventeen queue names were enumerated, all returning HTTP 401 confirming authenticated resources exist.

    Two OAuth device code flows work against Microsoft's corporate tenant (72f988bf-86f1-41af-91ab-2d7cd011db47). An attacker can generate a device code, trick a Microsoft employee into authenticating, and capture a token granting access to internal DevOps (powerbi.visualstudio.com) and Power Platform Admin Center.

    The Power Platform Admin Center exposes its full runtime configuration in HTML source, including client ID 065d9450-1e87-434e-ac2f-69af271549ed and complete OneCollector telemetry endpoint mappings for 12 sovereign and government environments.

The exposed data includes: TypeScript source code (1,390 files), internal mock framework with isTenantAdministrator toggle, Azure AD role object IDs, Microsoft tenant IDs, internal IP ranges (10.240.0.0/16, 10.224.0.0/12), DMTS error codes (55+), OpenAI integration error handling, internal DevOps repository URLs (msazure.visualstudio.com, powerbi.visualstudio.com), specific work items (Bug 732493, WI 795609, PR 831855), internal developer names, hardcoded test credentials (test@contoso.com, mock tenant 4d87d9fc-1a15-46db-aea1-e432cb0179ba), and 12 feature flags revealing upcoming functionality (SAP CDC connector, OneLake SSO, soft delete, VNet V2 API).

No authentication is required to access any of these JavaScript bundles, source maps, localization files, or telemetry injection endpoints. An attacker can download complete application source code from any of the 12 gateway portals or 6 internal Power BI deployments without any credentials. An attacker can inject telemetry events into Microsoft's internal Application Insights instances using any of the four confirmed keys. An attacker can generate device codes for OAuth flows and phish Microsoft employees to obtain tokens with elevated privileges.

These exposures represent a systemic design flaw affecting all Power BI / Fabric environments regardless of classification (production, test, sovereign, government, internal dogfood). The source map remains accessible as of June 7, 2026, despite the researcher's initial MSRC submission (VULN-193676) on June 6, 2026.

Hello,

Thank you for your report and for working with us to help protect customers. We have assessed your report as Low Severity and a 12/03/2026 resolve by date. I still need confirmation of the severity from our product group before I can progress this case.

The reported exposure consists solely of operational metadata and client-side implementation details. No customer data, authentication material, or server-side secrets are disclosed.

Claims regarding partner tenant IDs embedded in source maps are unsupported, as only mock tenant identifiers were observed. Similarly, the alleged telemetry injection impact is overstated—Application Insights instrumentation keys (iKeys) are not secrets and are not intended to provide authentication or access control per Microsoft documentation - https://learn.microsoft.com/en-us/azure/azure-monitor/app/connection-strings

The device code phishing scenario aligns with standard OAuth 2.0 authorization flows, which are a widely adopted industry-standard framework for delegated authorization rather than a vulnerability condition https://learn.microsoft.com/en-us/azure/api-management/authentication-authorization-overview

The following observations reflect by-design behavior or trivial exposure, not security issues:
• Application Insights telemetry injection via instrumentation keys
• OAuth device code / authorization flow generation
• Service Bus queue name enumeration patterns in unauthenticated/401 contexts
• Power Platform Admin Center configuration data present in client-side page source

Additionally, the disclosed content falls under operational metadata, which is commonly used for governance, automation, and resource management rather than representing sensitive data (for example, metadata used to support operational tracking and classification in Azure environments, as described in Define your tagging strategy).https://learn.microsoft.com/en-us/azure/cloud-adoption-framework/ready/azure-best-practices/resource-tagging

While this information may provide limited reconnaissance value that could support future attack development, it does not result in a security boundary bypass or expose sensitive data. The observed behaviors are consistent with expected platform functionality and publicly documented design characteristics.

Thank you again for partnering with us to help keep customers secure.

Best regards,
Microsoft Security Response Center (MSRC)
